# SugarBot Preparation Package Contract

This document defines the serialized package emitted by SugarPrep for a
downstream SugarBot consumer. SugarBot is external to this repository;
SugarPrep owns production of this package and its pre-commit validation.

## Canonical file set

An accepted bundle contains exactly these seven production files:

| File | Shape | Schema identity |
|---|---|---|
| `data.csv` | prepared tabular payload | `sugarprep.prepared-data.v1` |
| `layout.json` | raw SugarBot DataSpec object | `sugarbot.data-spec.v1` |
| `profile.json` | path-free profile object | `sugarprep.dataset-profile.v1` |
| `compiled-plan.json` | recipe and executable plan provenance | `sugarprep.compiled-plan.v1` |
| `warnings.json` | array of warning objects | `sugarprep.warnings.v1` |
| `rejects.csv` | rejected-row evidence | `sugarprep.rejects.v1` |
| `manifest.json` | accepted bundle index and evidence | `sugarprep.artifact-manifest.v1` |

The authoritative producer registry is
`src/sugarprep/artifacts/schemas.py`. The frozen consumer-shaped fixture is
`tests/fixtures/sugarbot_package_v1.json`. The two are tested independently so
a producer change cannot silently redefine consumer compatibility.

## Layout compatibility

`layout.json` is the raw DataSpec. It is not nested under `ingest`,
`data_spec`, or another SugarPrep wrapper. It requires a `time_col`, a non-empty
`value_cols`, and a `primary_value_col` included in `value_cols`. Every named
data column must exist in the prepared CSV header.

## Manifest

The manifest records:

- immutable bundle, draft, recipe, plan, and profile identities;
- source and output-independent counts;
- the exact filename mapping expected by the legacy consumer contract;
- one accepted entry per production artifact, including schema identity,
  media type, and content digest where possible;
- the complete result-validation and bundle-validation findings;
- the explicit acceptance decision and actor.

The manifest entry itself has no declared content digest because embedding its
own digest would be recursive. All other entries declare SHA-256 content
digests. `manifest.json` is generated by `artifacts`, passed to the store as
immutable bytes, and written in the same atomic transaction as the other six
files.

The package deliberately excludes source paths, artifact-store roots, and
`DatasetRef.storage_locator`. Dataset payload resolution remains an
infrastructure responsibility and is not part of a serialized schema.

## Reject compatibility

`rejects.csv` retains the stable header:

```text
source_row,output_column,source_column,transform,reason
```

The modern runtime maps `RejectedRow.source_row_number` to `source_row`, its
reason code to `transform`, and its user-readable message to `reason`. The two
column fields remain empty until rejection evidence gains stable column-level
ownership in the domain model.

## Validation boundary

`validation.sugarbot_contract.validate_sugarbot_package` accepts a filename to
bytes mapping. It does not open paths or interpret storage locators. The local
artifact store likewise does not construct schemas: it verifies supplied
metadata and digests, writes the already-serialized documents, copies the exact
prepared snapshot, and promotes the staging directory atomically.
